The `DataSource<T>` interface is the foundational abstraction for all data access in the grid. This interface's only responsibility is to provide mechanism to connect to external sources of data and execute commands against those sources.

- API datasource: Connect to an API endpoint that talks to a database: Provided.
- WASM datasource: Connect to WASM datasources in browser like duckdb / PGLite: Provided.
- In JS memory datasource: Access data stored in jsmemory (as array / object) and: Not Provided. Note - as WASM datasource is superior.

It provides a generic query execution contract with ref-counted lifecycle management,
allowing multiple consumers (pivot grid, flat table) to share a single underlying connection.

`DataSource` is an abstract class, we pack concrete implementation of some data sources in the grid that covers majority of the usecase.

```
DataSource<T> (interface)         — generic: execute, addRef, release
└── SqlDataSource (abstract)      — implements DataSource<string>, adds loadData + table
    ├── DuckDBDataSource          — Node.js duckdb
    └── DuckDBWasmDataSource      — Browser WASM duckdb
```

### What does query execution mean?

When grid needs data to show (during the load phase / during interactions), the relevant DataModel figures what data needs to be loaded, then DataModel for API datasource forwards the payload to the http api, similarly DataModel for SQL over WASM prepares right SQL to fetch data from source. This process is is called query exection. DataSource provides the standard for generic query exectuion.

### How does grid makes uses of `DataSource`?

1. User configures DataSource (API, WASM)
2. Grid looks at the configuration based on which the data needs to be loaded
3. Grid calls DataModel to figure which exact query (SQL / HTTP payload) needs to be executed
4. DataModel forward the query to DataSource
