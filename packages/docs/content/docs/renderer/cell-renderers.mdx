---
title: Cell Renderers
description: Cell renderers control how content is drawn inside grid cells. The grid has three cell types - data cells (the grid body), facet cells (row and column headers), and corner cells (intersection of row and column headers). Each cell type has a dedicated renderer signature. Renderers can be overridden per-column, per-facet-level, or conditionally via selection rules.
---

Every cell in the grid is rendered by a renderer function. There are three renderer types, one for each kind of cell:

- **Data cell renderer** (`CellRenderer`) - renders the value inside a data cell (the main grid body).
- **Facet cell renderer** (`FacetCellRenderer`) - renders facet cells (row and column headers).
- **Facet header renderer** (`FacetHeaderRenderer`) - renders the level label for a facet track (e.g. "Region", "Quarter").

All three share the same ownership convention: return content and the layout places it in the DOM, or return `void` to signal that you have taken ownership of the container (used for framework rendering like React).

## Data cell renderers

A `CellRenderer` receives the cell's value and a context object, and returns content to display.

```json doc-gen:file
{ "file": "packages/grid/src/renderer/cell-renderers.ts#cell-renderer", "codeblock": { "lang": "ts" } }
```

### Return values

| Return type | Behavior |
|---|---|
| `string` | Set as the cell's `innerHTML`. Use for simple text or HTML strings. |
| `HTMLElement` | Appended as the cell's child. |
| `HTMLElement[]` | All elements appended as children. |
| `void` (undefined) | The layout does not touch the container. The renderer owns it - used when a framework like React calls `createRoot` on the container. |

### Assigning renderers

Data cell renderers are assigned per column via [`VTrackDef.renderer`](/docs/api-references/type-references#vtrackdef) in the viewmodel options. Columns without a renderer get the default `textRenderer`.

```ts
const options: GridDataViewModelOptions = {
  vTrackDefs: [
    undefined,                          // column 0: default textRenderer
    { renderer: myBarRenderer },        // column 1: custom renderer
    { renderer: sparklineRenderer, cellHeight: 40 },  // column 2: custom with fixed height
  ],
};

const viewModel = new PivotDataViewModel({ ...params, options });
```

### Writing a custom data cell renderer

A renderer receives the raw cell value and a context. Use `ctx.container` for styling or as a mount point.

```ts
import { CellRenderer } from "grid";

const percentRenderer: CellRenderer<number> = (data, ctx) => {
  ctx.container.style.display = "flex";
  ctx.container.style.alignItems = "center";
  ctx.container.style.gap = "6px";

  const bar = document.createElement("div");
  bar.style.width = `${Math.min(100, Math.max(0, data))}%`;
  bar.style.height = "4px";
  bar.style.backgroundColor = data >= 50 ? "#4caf50" : "#f44336";
  bar.style.borderRadius = "2px";

  const label = document.createElement("span");
  label.textContent = `${data}%`;

  return [bar, label];
};
```

### Optional cellHeight and sampleData

The layout measures row height before the first render by calling each column's renderer with a sample value. By default it uses the first row's value from the viewmodel. You can control this:

- `cellHeight` - skip measurement entirely; use this fixed pixel height. Useful for renderers that produce fixed-size content like charts.
- `sampleData` - provide a representative value for measurement instead of the first row. Useful when the first row may not represent typical content.

```ts
const chartDef: VTrackDef<number[]> = {
  renderer: createChartRenderer({ chartType: "line", minHeight: 30 }),
  cellHeight: 30,
  sampleData: [1, 2, 3, 4, 5],
};
```

## Facet cell renderers

A `FacetCellRenderer` renders a single facet cell - the value labels in row and column headers.

```json doc-gen:file
{ "file": "packages/grid/src/renderer/types.ts#facet-cell-renderer", "codeblock": { "lang": "ts" } }
```

- `path` gives you the full facet context. For a column facet cell at level 1 showing "Revenue" under "Q1", the path is `["Q1", "Revenue"]`.
- `flatMeta` is only present for row facets rendered by `GroupedRowLayout`. It contains `depth`, `isLeaf`, and `isExpanded` for the row.
- `ctx.render(viewModel)` triggers a full re-render with the given viewmodel. Use it for interactive facet cells - for example, clicking a row facet to expand/collapse a group.
- Instead of returning a plain string or element, a facet renderer can return a `FacetCellContent` object to place content in up to three slots: `left` (e.g. expand/collapse icon), `content` (the label), and `right` (e.g. sort indicator).

```ts
const groupFacetRenderer: FacetCellRenderer = (data, dataCtx, ctx) => {
  const icon = document.createElement("span");
  icon.textContent = dataCtx.flatMeta?.isExpanded ? "▼" : "▶";
  icon.style.cursor = "pointer";
  icon.onclick = () => {
    // toggle expand/collapse and re-render
    toggleGroup(dataCtx.index);
    ctx.render(updatedViewModel);
  };

  return {
    left: icon,
    content: data ?? "",
  };
};
```

### Assigning facet renderers

Facet renderers are set via [`FacetDef.trackRenderer`](/docs/api-references/type-references#facetdef) in the viewmodel options:

```ts
const options: GridDataViewModelOptions = {
  facetDefs: {
    row: [{ text: "Region", trackRenderer: groupFacetRenderer, headerRenderer: defaultFacetHeaderRenderer }],
    col: [{ text: "Quarter", trackRenderer: defaultFacetRenderer, headerRenderer: defaultFacetHeaderRenderer }],
    axis: "col",
  },
};
```

## Facet header renderers

A `FacetHeaderRenderer` renders the level label - the label cell that identifies a facet track (e.g. "Region", "Quarter").

```json doc-gen:file
{ "file": "packages/grid/src/renderer/types.ts#facet-header-renderer", "codeblock": { "lang": "ts" } }
```

The `text` argument is the `FacetDef.text` value (e.g. "Region"). Use `ctx.render` for interactive headers - for example, clicking a column header to sort.

```ts
const sortableHeaderRenderer: FacetHeaderRenderer = (text, ctx) => {
  const label = document.createElement("span");
  label.textContent = text;
  label.style.cursor = "pointer";
  label.onclick = () => {
    // apply sort and re-render
    applySort(text);
    ctx.render(updatedViewModel);
  };
  return label;
};
```

## Built-in renderers

The grid ships with several built-in renderers:

### textRenderer

The default data cell renderer. Displays the value as a single-line string with text overflow ellipsis.

```ts
const textRenderer: CellRenderer<unknown> = (data, ctx) => {
  ctx.container.style.display = "inline-block";
  ctx.container.style.overflow = "hidden";
  ctx.container.style.textOverflow = "ellipsis";
  ctx.container.style.whiteSpace = "nowrap";
  return data == null ? "" : String(data);
};
```

Columns without a `VTrackDef.renderer` use this by default.

### createChartRenderer

A factory that returns a data cell renderer for inline SVG charts. Supports `"line"` and `"bar"` chart types.

```ts
import { createChartRenderer, defaultChartConfig } from "grid";

const sparkline = createChartRenderer({ chartType: "line", color: "#1976d2" });
const barChart = createChartRenderer({ chartType: "bar", minWidth: 100, minHeight: 24 });
```

```ts
interface ChartConfig {
  chartType: "line" | "bar";
  minWidth: number;      // SVG width in pixels. Default: 80
  minHeight: number;     // SVG height in pixels. Default: 20
  padding: number;       // internal padding in pixels. Default: 4
  color: string;         // stroke/fill color. Default: "#1976d2"
  strokeWidth: number;   // line stroke width (line charts only). Default: 2
}
```

The renderer expects `number[]` as cell data. Set `cellHeight` on the `VTrackDef` to match `minHeight`:

```ts
const options: GridDataViewModelOptions = {
  vTrackDefs: [
    undefined,
    {
      renderer: createChartRenderer({ chartType: "line" }),
      cellHeight: 20,
      sampleData: [1, 2, 3],
    },
  ],
};
```

### defaultFacetRenderer

The default facet cell renderer. Returns the value as a string; `null` becomes `""`.

```ts
const defaultFacetRenderer: FacetCellRenderer = (data) => {
  return data == null ? "" : String(data);
};
```

### defaultFacetHeaderRenderer

The default facet header renderer. Returns the text as-is; `null` becomes `""`.

```ts
const defaultFacetHeaderRenderer: FacetHeaderRenderer = (text) => {
  return text ?? "";
};
```

## Framework rendering (void return)

When a renderer returns `void`, the layout skips placing content in the DOM - it assumes the renderer has taken ownership of the container. This is the pattern for React, Vue, or any framework that manages its own DOM tree.

The key constraint: the layout measures cell dimensions (via `getBoundingClientRect`) immediately after calling renderers for column auto-sizing. Framework renders that are async (like React's default batching) must be flushed synchronously before measurement happens.

### How React rendering works

The `packages/frameworks` React bindings handle this automatically via `ReactCellAdapter`. The adapter:

1. Creates a React root (`createRoot`) bound to the cell's `ctx.container`.
2. Returns `void` from the renderer so the layout does not touch the container.
3. Batches all `root.render()` calls and flushes them synchronously (via `flushSync`) before measurement.

```ts
// Internal: how the React adapter wraps a React component into a CellRenderer
createNativeDataCellRenderer(Component: FC<CellProps>): CellRenderer<any> {
  return (data: any, ctx: RendererContext) => {
    const root = getOrCreateRoot(ctx.key, ctx.container);
    root.render(<Component value={data} cell={ctx.container} />);
    // returns void — layout leaves the container alone
  };
}
```

When using the React `DataGrid` component or hooks like `useFlatGrid`/`usePivotGrid`, you pass React components directly - the adapter wraps them for you:

```tsx
import { FC } from "react";
import { CellProps } from "frameworks";

const PercentCell: FC<CellProps<number>> = ({ value }) => (
  <div style={{ display: "flex", alignItems: "center", gap: 6 }}>
    <div style={{
      width: `${Math.min(100, Math.max(0, value))}%`,
      height: 4,
      backgroundColor: value >= 50 ? "#4caf50" : "#f44336",
      borderRadius: 2,
    }} />
    <span>{value}%</span>
  </div>
);

// In useFlatGrid columns config:
const columns = [
  { renderer: PercentCell },
];
```

### Writing a void renderer without React

If you are using another framework or a custom rendering library, follow the same pattern:

1. On first call (when the cell is new), mount your framework's root on `ctx.container`.
2. On subsequent calls (same key, cell reused), update the existing root.
3. Return `void` so the layout does not replace your content.
4. Handle cleanup when the cell is released - pass `onCellRelease` to the Grid constructor.

```ts
const grid = new Grid(config, mountEl, "flat", {
  onCellRelease: (key, cell) => {
    // Clean up your framework root for this cell
    myFramework.unmount(cell);
  },
});
```

The `key` is stable across render frames for the same logical cell position, so you can use it to cache framework roots.

## Conditional renderers via selection rules

`VTrackDef.renderer` and `FacetDef.trackRenderer` apply to an entire column or facet level. To override the renderer for specific cells based on their facet context or value, use [selection rules](/docs/renderer/selections).

`grid.selectAll(predicate)` matches facet cells by dimension name and value. Chain `.prop({ cellRenderer })` to override the data cell renderer, or `.prop({ trackRenderer })` to override the facet cell renderer, for matching cells only.

```ts
// Use a bar renderer only for Revenue data cells
grid
  .selectAll((dim, dimVal) => dim === "Measure" && dimVal === "Revenue")
  .prop({ cellRenderer: barRenderer });

// Use a custom facet renderer only for the Region dimension
grid
  .selectAll((dim) => dim === "Region")
  .prop({ trackRenderer: regionFacetRenderer });
```

To target data cells by their value, chain `.selectAllCell(predicate)`:

```ts
// Use a red-text renderer for negative revenue cells
grid
  .selectAll((dim, dimVal) => dim === "Measure" && dimVal === "Revenue")
  .selectAllCell((value) => value < 0)
  .prop({ cellRenderer: negativeValueRenderer });
```

See [Selection Rules](/docs/renderer/selections) for the full API.

## Renderer selection priority

During rendering, the layout resolves which renderer to use for each cell in this order:

1. **Selection rule override** - if a [selection rule](/docs/renderer/selections) matches and provides a `cellRenderer` (for data cells) or `trackRenderer` (for facet cells), it takes priority.
2. **VTrackDef/FacetDef renderer** - the renderer set on the column's `VTrackDef` or facet level's `FacetDef`.
3. **Default renderer** - `textRenderer` for data cells, `defaultFacetRenderer` for facet cells, `defaultFacetHeaderRenderer` for facet headers.

When multiple selection rules match and set a renderer override, the last matching rule wins (rules are evaluated in insertion order).
